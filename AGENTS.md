# AGENTS.md — Graphical AI Tutor Agent Rules

## Mission

Build Graphical AI Tutor as a student-first application on top of `yctimlin/mcp_excalidraw`.

The student must NOT need a coding agent to use the product.

## Source of truth

Before changing architecture or behavior, consult:

- `docs/PRD.md`
- `docs/TRD.md`
- `docs/UI-UX.md`
- `docs/Architecture.md`

## Mandatory workflow for every development prompt

1. Read this file.
2. Read the relevant project docs.
3. Use Graphify as codebase memory for cross-file/architectural work.
4. Use Matt Pocock skills where applicable.
5. Apply ECC engineering practices.
6. Apply Ponytail's YAGNI/minimal-code rules.
7. Use the Excalidraw skill/tooling for canvas-related work.
8. For user-facing behavior, verify the running application with Reticle.
9. For security-sensitive changes, run Strix within the authorized scope.
10. For large iterative work, use Ralph Loop.
11. Run CodeRabbit review before substantial work is considered complete.

"Use" means consult/apply the relevant workflow and verify its result. Do not blindly invoke an irrelevant tool merely to satisfy a checklist.

## Graphify

Graphify is the persistent codebase-memory layer.

Keep the graph current after major changes.

Recommended commands:

```bash
uv tool install graphifyy
graphify install
graphify .
```

Do not commit secrets into Graphify output.

## Excalidraw rules

- Prefer native editable Excalidraw elements.
- Never replace the canvas with a static image when native elements can represent the concept.
- Preserve student-created content.
- Modify existing elements when the user asks to edit a diagram.
- Use snapshots before destructive multi-element operations.
- Validate drawing commands before sending them to the canvas.
- Do not let LLM output execute arbitrary code.
- Use the upstream `mcp_excalidraw` infrastructure instead of recreating it.

## Tutor rules

The tutor is a teacher.

It must:
- adapt to Beginner / Intermediate / Pro,
- explain instead of merely answer,
- correct misconceptions,
- use visuals when useful,
- remember lesson context,
- avoid unnecessary redraws,
- be honest about uncertainty.

## Security rules

Never:
- log API keys,
- put API keys in prompts,
- store API keys in canvas elements,
- export API keys,
- execute shell commands generated by the tutor,
- trust unvalidated drawing JSON,
- allow arbitrary outbound URL fetching without SSRF protection.

## Voice rules

Voice is optional.

Text must always work when voice fails.

MVP:
- browser SpeechRecognition where available,
- browser SpeechSynthesis.

Advanced:
- local faster-whisper STT,
- local Piper TTS.

Do not make Python mandatory unless the feature requires it.

## Dependency rules

Ponytail/YAGNI applies.

Before adding a package:
1. Check whether the existing repository already provides the capability.
2. Check whether the platform provides it natively.
3. Check whether an installed dependency already provides it.
4. Add a new package only when justified.

## UI rules

The canvas is the primary surface.

The app must feel like an interactive teacher + whiteboard, not a developer dashboard.

## Completion rule

Never report "done" merely because the code compiles.

A substantial feature is done only when:
- tests pass,
- the real user flow works,
- canvas behavior is verified,
- Reticle passes where applicable,
- security checks are complete where applicable,
- CodeRabbit findings are resolved or explicitly accepted,
- docs remain consistent.
